\section{第 5 题 控制一个可清理的后台任务}

\subsection{实验内容}

如图\ref{fig:创建worker脚本}所示，使用vim编辑器创建 worker.sh。脚本通过 trap 命令设置了 TERM 和 INT 两个信号的处理函数，当脚本收到这两个信号时，会执行 \verb|echo CLEAN_EXIT >> cleanup.log; exit 0|，即向 cleanup.log 写入 CLEAN\_EXIT 后以退出码 0 正常结束；随后进入无限循环，每秒钟打印一次计数器 n 并将其自增。

\end{figure}

如图\ref{fig:赋予执行权限5}所示，使用 chmod +x 命令为 worker.sh 添加执行权限。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{截屏2026-09-03 10.06.12.png}
    \caption{为 worker.sh 添加执行权限}
    \label{fig:赋予执行权限5}
\end{figure}

如图\ref{fig:前台启动并挂起}所示，在前台启动 worker.sh，并通过重定向把 stdout 写入 stdout.log、stderr 写入 stderr.log；随后使用 Ctrl-Z 挂起该任务，从图中可以看到 zsh 输出了 suspended 提示，说明任务已被挂起。

\end{figure}

如图\ref{fig:后台继续运行}所示，使用 bg 命令让被挂起的任务转到后台继续运行，并使用 jobs 命令确认任务状态。从图中可以看到，jobs 输出 \verb|[1] + running ./worker.sh > stdout.log 2> stderr.log|，说明任务正在后台运行。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{截屏2026-09-03 10.07.15.png}
    \caption{使用 bg 让任务后台继续运行}
    \label{fig:后台继续运行}
\end{figure}

如图\ref{fig:发送SIGTERM}所示，使用 jobs -p 取得后台任务的进程号（PID），并通过 kill 命令发送 SIGTERM 信号结束任务，全程没有手工抄写 PID，也没有使用 kill -9。任务收到 SIGTERM 信号后触发了 trap 中设置的清理逻辑，最终以 \verb|[1] + done| 结束（done 表示进程以退出码 0 正常退出，而非被信号强制终止），随后 jobs 命令输出为空，说明任务已经退出。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{截屏2026-09-03 10.08.13.png}
    \caption{发送 SIGTERM 信号结束任务}
    \label{fig:发送SIGTERM}
\end{figure}

在图\ref{fig:发送SIGTERM}中，kill 为发送信号命令，-TERM 表示发送 SIGTERM（终止）信号，jobs -p 用于输出后台任务的进程号。需要注意的是，zsh 中直接执行 \verb|kill -TERM $(jobs -p)| 时，命令替换 \verb|$(jobs -p)| 展开后得到的是任务的完整状态行而非纯 PID，导致出现 illegal pid 报错，需要先正确提取出纯 PID 再发送信号。

如图\ref{fig:确认CLEANEXIT}所示，使用 grep 命令在 cleanup.log 中查找 CLEAN\_EXIT，输出结果为 CLEAN\_EXIT，说明脚本的 trap 清理逻辑被正确触发，任务已经干净地退出。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{截屏2026-09-03 10.08.29.png}
    \caption{确认 cleanup.log 中出现 CLEAN\_EXIT}
    \label{fig:确认CLEANEXIT}

\section{第 7 题 用调试器定位归并排序缺陷}

\subsection{实验内容}

如图\ref{fig:创建mergesort}所示，使用vim编辑器创建 merge\_sort.py，内容为题目给定的存在缺陷的归并排序代码，并用 cat 命令查看文件内容。其中 merge 函数 else 分支中的 \verb|result.append(right[i])| 处存在缺陷（正确应为 \verb|right[j]|）。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{截屏2026-09-06 11.26.35.png}
    \caption{创建 merge\_sort.py}
    \label{fig:创建mergesort}
\end{figure}

如图\ref{fig:运行归并排序}所示，直接运行 merge\_sort.py，可以看到输出结果错误（或抛出异常），确认代码存在缺陷。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{截屏2026-09-06 11.27.15.png}
    \caption{运行 merge\_sort.py 结果错误}
    \label{fig:运行归并排序}
\end{figure}

如图\ref{fig:pdb调试}所示，使用 \verb|python3 -m pdb merge_sort.py| 启动调试器：先用 l 命令查看源码，再在 merge 函数的第 8 行（缺陷行）使用 b 8 设置断点，用 c 命令继续执行到断点处，然后使用 p 命令打印 i、j、left[i]、right[j] 的值。从图中可以看到，此时 i=0、j=0、left[i]=3、right[j]=1，即 left[i] > right[j]，本应把较小的 right[j] 加入结果，但缺陷代码取的是 right[i]，因此导致排序错误。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{截屏2026-09-06 11.31.45.png}
    \caption{使用 pdb 调试并观察变量}
    \label{fig:pdb调试}
\end{figure}

在图\ref{fig:pdb调试}中，b 8 表示在第 8 行设置断点，c 表示继续执行，p 表示打印表达式，n 表示单步执行下一条语句，q 表示退出调试器。通过观察 i、j、left[i]、right[j] 的值，可以定位到缺陷：else 分支中应使用 \verb|right[j]| 而非 \verb|right[i]|。将 merge 函数中的 \verb|result.append(right[i])| 修改为 \verb|result.append(right[j])| 即可完成最小修复，没有用 sorted 替换归并排序。

\section{第 8 题 先测量，再优化慢速词频程序}

\subsection{实验内容}

如图\ref{fig:创建词频程序}所示，使用vim编辑器创建 generate\_words.py 和 wordfreq.py。generate\_words.py 使用固定的随机种子生成包含 1000 个不同词、共 30000 个词的 words.txt；wordfreq.py 通过列表 unique 逐词判断去重，统计不重复词的数量。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{截屏2026-09-06 17.05.07.png}
    \caption{创建 generate\_words.py 和 wordfreq.py}
    \label{fig:创建词频程序}
\end{figure}

如图\ref{fig:生成词表}所示，运行 \verb|python3 generate_words.py| 生成 words.txt。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{截屏2026-09-06 17.10.56.png}
    \caption{生成 words.txt}
    \label{fig:生成词表}
\end{figure}

如图\ref{fig:time原程序}所示，使用 time 命令运行原程序 wordfreq.py 两次，记录耗时。两次输出 count=1000，耗时分别为 0.149s 和 0.127s。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{截屏2026-09-06 17.11.23.png}
    \caption{使用 time 运行原程序两次}
    \label{fig:time原程序}
\end{figure}

如图\ref{fig:cProfile分析}所示，使用 \verb|python3 -m cProfile -s cumulative wordfreq.py| 进行性能分析。从输出可以看到，程序共 1012 次函数调用，累计耗时 0.094s，主要耗时集中在 wordfreq.py 第 1 行的模块级代码（cumtime 0.094s），即 for 循环中对列表 unique 的 \verb|word not in unique| 判断。由于列表的成员判断复杂度为 $O(n)$，整体复杂度为 $O(n^2)$，这是程序的性能瓶颈。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{截屏2026-09-06 17.12.04.png}
    \caption{使用 cProfile 分析耗时}
    \label{fig:cProfile分析}
\end{figure}

如图\ref{fig:创建优化程序}所示，创建优化后的 wordfreq\_opt.py，将去重用的列表 unique 改为集合 set：\verb|unique = set(words)|。集合的成员判断平均复杂度为 $O(1)$，可以把整体复杂度从 $O(n^2)$ 降到 $O(n)$，且不改变最终的 count 结果，也没有写死 1000。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{截屏2026-09-06 17.14.17.png}
    \caption{创建优化后的 wordfreq\_opt.py}
    \label{fig:创建优化程序}
\end{figure}

如图\ref{fig:time优化程序}所示，使用相同输入再次运行优化后的程序两次，耗时分别为 0.053s 和 0.043s。

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{截屏2026-09-06 17.14.45.png}
    \caption{使用 time 运行优化程序两次}
    \label{fig:time优化程序}
\end{figure}

优化前两次耗时为 0.149s 和 0.127s，中位数为 0.138s；优化后两次耗时为 0.053s 和 0.043s，中位数为 0.048s。加速比为 $0.138 / 0.048 \approx 2.9$，即优化后性能约提升到原来的 2.9 倍，且最终 count 仍为 1000，结果保持不变。
